# RB-07 · API errors and cache problems

Fictional runbook. Used for: ticketing-api, cache-redis.

Steps marked [READ] only look; steps marked [CHANGE] need approval (policy section 5).

1. [READ] `check_error_rate`: Check the 5xx rate and when it started, and any deploy since then.
2. [READ] `check_cache_health`: Check the cache's memory and evictions.
3. [CHANGE] `clear_cache`: Clear the shared cache, if evictions are high.
4. [CHANGE] `rollback_deploy`: Roll back the last deploy, only if the cache is healthy and errors started with the deploy.
