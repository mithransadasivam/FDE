# ENG-801 · The MCP server checks every token

**Type:** feature · **Priority:** Must · **Day 8, Activity 1** · **Story:** only the bank's staff, signed in, reach the bank's systems

## Story

As Helen Achebe, the MLRO, I want the MCP server to accept only tokens the bank's sign-in service issued for it, still valid, with the permissions the request needs, so that nobody can reach the CRM or the KYC exceptions with a forged, stolen, expired or borrowed token.

## Acceptance criteria

1. `verify_access_token(token, jwks, issuer, audience, required_scopes, now)` in `backend/app/integration/tokens.py` returns an `Identity`, or raises `TokenRejected` with the first reason that applies, word for word as its docstring lists them.
2. Only RS256 is accepted, with a key from the bank's JWKS chosen by the token's `kid`. `alg: none`, HS256 and unknown keys are refused before anything in the token is trusted.
3. The audience must be the MCP server itself (`http://localhost:8200/mcp`): a token issued for the CRM is refused here.
4. On **Integrations → Sign-in**, 9 of 9 tokens are handled as expected: Tom's is accepted, the other eight are refused.
5. Claude Code connects: `claude mcp add --transport http kestrelmoor-kyc http://localhost:8200/mcp`, then `/mcp` signs you in at the bank and lists 7 tools.

## Files you change

- `backend/app/integration/tokens.py`: fill in `verify_access_token()`. Nothing else.

`PyJWT` (`import jwt`) is in `requirements.txt`. The MCP server (`mcp_server.py`, done) calls your function for every request and turns the Identity into the SDK's `AccessToken`.
