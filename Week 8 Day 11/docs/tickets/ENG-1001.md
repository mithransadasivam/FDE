# ENG-1001 · Work one round of a case as checkpoints: propose, wait for the person, write

**Type:** feature · **Priority:** Must · **Day 10, Activity 1** · **Story:** a crash while Tom decides loses nothing

## Story

As Tom Reyes, a KYC analyst, I want the agent's proposal to wait for my decision for as long as I need, through any restart, so that I approve it once, the agent never works the same case twice, and nothing is written until I say yes.

## The problem today

`work_round()` in `backend/app/workflow/case.py` runs the whole Day 9 agent inside one step, `steps.agent_round()`: the agent works the case, waits **in memory** for Tom's decision, then presses Confirm itself. DBOS only saves a step when it finishes. Crash the worker while KX-1001 waits for Tom, and the step starts again from the top: the agent works the case a second time (new model calls), and Tom gets a second approval card. The first card no longer leads anywhere.

## Acceptance criteria

1. `work_round(key, ticket_id, prompt, round_no, policy)` makes three checkpoints, as its docstring lists:
   - `steps.propose()`: a step. The agent works the case up to CaseFlow's confirm screen and saves the approval it needs.
   - `DBOS.recv(<the approval's id>, timeout_seconds=engine.days(policy["approval_expires_after_days"]))`: the workflow waits for the decision. The console sends it on the approval's id as the topic.
   - `steps.apply()`: a step. Plain code records exactly the approved outcome in CaseFlow Classic and reads it back.
2. If the agent ends without proposing (`p["approval"]` is `None`), return `{"end": p["status"], **p}`: no wait.
3. No decision in time: call `steps.expire()` and end `expired`. Rejected: end `rejected`, and write nothing.
4. No `time.sleep()`, no `time.time()`, and nothing that touches the world outside a step (CLAUDE.md rule 18).
5. On **Workflows → One case, for days**: start KX-1001, press **Crash the worker now** while it waits for you, and the case still shows **1 agent run**. Approve it once: CaseFlow records Request more information.
