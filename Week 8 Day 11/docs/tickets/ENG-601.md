# ENG-601 · Parse every document the bank sends, whatever its form

**Type:** feature · **Priority:** Must · **Day 6, Activity 1** · **Story:** read the October batch at scale

## Story

As the FDE, I want every document turned into the same list of words with their positions, whether the bank sent a digital PDF, a scanned PDF or a JPG, so that everything after this step (the model, the grounding, the Review queue) works the same way for all 200 documents.

## Acceptance criteria

1. `text_layer_words(pdf_path)` in `backend/app/pipeline/parse.py` returns the words of a PDF's first page from its text layer, exactly as its docstring describes: pdfplumber's `extract_words(x_tolerance=1.5, y_tolerance=3)`, ids `w001`, `w002`… in pdfplumber's order, boxes as fractions of the page (4 decimals), confidence 1.0. A PDF with no text layer gives `[]`.
2. `parse_document(doc_id)` returns a `ParsedPage`: a PDF with at least `MIN_TEXT_WORDS` words is read from its text layer (`source "text_layer"`); a PDF with fewer is a scan saved as a PDF, read from the bank's OCR file (`source "ocr"`); a JPG is read from the OCR file. An unknown document raises `KeyError`.
3. On **Pipeline → Parse**, the October batch shows 108 documents read from the text layer and 92 from the bank's OCR, including 12 PDFs with no text layer.

## Files you change

- `backend/app/pipeline/parse.py`: fill in `text_layer_words()` and `parse_document()`. Nothing else.

`ocr_file_words()` is in the same file (done). `document_file()` and `ocr_file()` are in `backend/app/pipeline/documents.py` (done). pdfplumber is a new package for Day 6: it is in `backend/requirements.txt`.
