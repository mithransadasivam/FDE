# ENG-701 · Check every query before it runs

**Type:** feature · **Priority:** Must · **Day 7, Activity 1** · **Story:** a question can never change, copy or leak the bank's data

## Story

As Helen Achebe, the MLRO, I want every query the data agent writes to be checked before it reaches the warehouse, so that no question, however it is worded, can change CaseFlow, read a file, or reach a table the agent was not given.

## Acceptance criteria

1. `check_query(sql, approved, max_rows, blocked_functions)` in `backend/app/data_agent/validator.py` returns a `Check` exactly as its docstring describes: refused with every reason that applies, in order and word for word, or allowed with the query ready to run.
2. It reads the query's structure with `sqlglot` (`sqlglot.parse(sql, read="duckdb")`), never its text: a comment, capital letters or a second statement after a semicolon cannot get past it.
3. An allowed query always has a limit on its outermost query: added when missing, lowered when above `max_rows` (1,000 in `semantic/access.yml`).
4. On **Data agent → Safety**, all 15 harmful queries are refused and the 3 safe ones run with a limit. The cross join (P18) passes your check and is stopped by the cost check (done) before it runs.

## Files you change

- `backend/app/data_agent/validator.py`: fill in `check_query()`. Nothing else.

`_kind()` and `_function_name()` are in the same file. `sqlglot` is in `requirements.txt`. The approved tables, the row limit and the blocked functions come from `semantic/access.yml` (done).
