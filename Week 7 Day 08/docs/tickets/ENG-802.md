# ENG-802 · Call the bank's systems as the person, not as the console

**Type:** fix · **Priority:** Must · **Day 8, Activity 2** · **Story:** the bank's audit says who did it

## Story

As Helen Achebe, the MLRO, I want every call the MCP server makes to the CRM and the KYC exceptions system to carry the person who asked, so that each system applies that person's permissions and its audit log names them, not the console.

## The problem today

`downstream_token()` in `backend/app/integration/downstream.py` uses the console's service account (`svc-fde-console`). Every call works, so nothing looks broken. But Tom sees every team's customers, Helen can write notes the MLRO may not write, Grace cannot assign work, and the CRM's audit log says `svc-fde-console` for everyone.

## Acceptance criteria

1. `downstream_token(identity, audience, http)` exchanges the person's token at the bank's token endpoint (OAuth 2.0 Token Exchange, RFC 8693), exactly as its docstring describes, and returns the new token.
2. The new token is for the target system (`aud` = `crm`, `kyc-exceptions` or `documents`), is issued to the person (`sub`), and says the MCP server acts for them (`act` = `{"sub": "fde-mcp"}`).
3. Never send the person's own token to another system (token passthrough), and never use the service account.
4. On **Integrations → Act as the person**, Tom finds 12 customers, all in North 1, and the audit log shows `tom.reyes via fde-mcp`.

## Files you change

- `backend/app/integration/downstream.py`: replace the body of `downstream_token()`. Keep `service_account_token()`: other code may need it later, with its own approval.
