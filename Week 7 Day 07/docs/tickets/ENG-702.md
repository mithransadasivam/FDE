# ENG-702 · Row security: every query sees only what its user may see

**Type:** feature · **Priority:** Must · **Day 7, Activity 2** · **Story:** the same rules as CaseFlow, whatever the question

## Story

As Helen Achebe, the MLRO, I want an analyst to see only their own team's cases, a team lead only their region's, and my reports never to show a customer's name, so that Ask the data follows the bank's access policy. That must not depend on what the model decides to write.

## Acceptance criteria

1. `apply_row_security(sql, teams, row_filters, masked_columns)` in `backend/app/data_agent/row_security.py` returns the query rewritten exactly as its docstring describes.
2. Every table with a row filter is replaced by a subquery of the same name, wherever it appears: `FROM`, `JOIN`, a CTE, a subquery, either side of a `UNION`. The subqueries you add are not rewritten again.
3. `teams=None` (Helen) adds no filter. A masked column (`caseflow.customers.customer_name`) reads `[hidden]`, through `SELECT * REPLACE ('[hidden]' AS customer_name)`.
4. On **Data agent → Row security**, all 30 checks (10 queries × 3 people) match the expected rows: no leaks.

## Files you change

- `backend/app/data_agent/row_security.py`: fill in `apply_row_security()`. Nothing else.

The filters and roles are in `semantic/access.yml`; `access.teams_for()` turns a person into team ids (done). The agent calls your function after `check_query()` and before the warehouse (done).
