# ENG-501 · Call the model on Amazon Bedrock, in London

**Type:** feature · **Priority:** Must · **Day 5, Activity 1** · **Story:** run UC1 inside the bank's AWS account

## Story

As the FDE, I want the console to call the model through Amazon Bedrock's Converse API in the bank's own AWS account, so that the pilot needs no outside AI service and no API key (Helen's rules from Day 1).

## Acceptance criteria

`BedrockClient` in `backend/app/llm.py`, exactly as the docstrings describe:

1. `request(system, messages)` returns the Converse request:
   - `modelId` is the client's model ID
   - `system` is `[{"text": system}]`
   - each message becomes `{"role": …, "content": [{"text": …}]}`
   - `inferenceConfig` is `{"temperature": 0, "maxTokens": 2000}`
   - when a guardrail ID is set, `guardrailConfig` is `{"guardrailIdentifier": …, "guardrailVersion": … (or "DRAFT"), "trace": "enabled"}`
2. `complete(system, messages)` sends exactly that request with `self.runtime.converse(**…)` and returns the reply's text: every `text` block of `output.message.content`, joined with nothing between them.
3. Each call adds one entry to `self.calls`: `input_tokens` and `output_tokens` from `usage`, `latency_ms` from `metrics.latencyMs`, and `stop_reason`.
4. `stopReason` `guardrail_intervened` raises `GuardrailBlocked("reply", <the reply's text>)`.
5. A botocore `ClientError` raises `LLMError` with the error code and the hint from `BEDROCK_HINTS`.
6. On **Pilot → Platform**, *Run the check* shows the Converse request for D03-001, with your model ID and a `guardrailConfig`.

## Files you change

- `backend/app/llm.py`: fill in `BedrockClient.request()` and `BedrockClient.complete()`. Nothing else.

`ask_json()` already calls `client.complete()` for every real client, and retries once. `llm_client()` builds a `BedrockClient` when `FDE_LLM_PROVIDER=bedrock`.
