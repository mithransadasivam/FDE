# ENG-1003 · Every write happens once, even when the worker crashes halfway through a step

**Type:** feature · **Priority:** Must · **Day 10, Activity 3** · **Story:** an applicant never gets the same letter twice

## Story

As Helen Achebe, the MLRO, I want every message to an applicant and every outcome in CaseFlow Classic to be written exactly once, so that an applicant is never sent the same request twice and a case never has two outcomes for one decision. A message to an applicant is a regulated communication.

## The problem today

DBOS saves a step's output when the step finishes. If the worker dies after a step has written to the bank but before the step finished, the step runs again: "at least once". In `backend/app/workflow/writes.py`:

- `idempotency_key()` returns a new random value every time. The contact gateway honours an `Idempotency-Key`, but a new key for each attempt is no key at all: crash right after KX-1004's request is sent, and the applicant gets it twice.
- `already_recorded()` always says no. CaseFlow Classic has no keys, so the apply step must read the case history before it writes. Crash right after CaseFlow confirms KX-1001's outcome, and the case gets two outcomes.

## Acceptance criteria

1. `idempotency_key(workflow_id, step_id)` returns `f"{workflow_id}:{step_id}"`: the same key every time the same step runs, and a different key for every other write.
2. `already_recorded(history, marker)` is `True` when a line of the case history contains the marker exactly, brackets included: `[case-KX-1001-1 r1]` is not found in a line that has `[case-KX-1001-1 r12]` or `[case-KX-1001-11 r1]`.
3. Every write is listed in data/Day10_Slide21_writes.csv with how it is made safe (CLAUDE.md rule 19).
4. On **Workflows → Crashes and writes**, arm `after_send_request` for KX-1004 and run the case: the bank holds **1** request. Arm `after_confirm` for KX-1001: CaseFlow holds **1** outcome for round 1.

## Files you change

- `backend/app/workflow/writes.py`: replace the bodies of `idempotency_key()` and `already_recorded()`. Keep `outcome_marker()` and `post()`.
