# ENG-901 · Find each control by what it is, and check what CaseFlow saved

**Type:** fix · **Priority:** Must · **Day 9, Activity 1** · **Story:** the agent does what it says it did

## Story

As Grace Mensah, KYC team lead, I want the operations agent to press the control it means to press in CaseFlow Classic, and to read the screen back after it saves, so that it never records something nobody chose, and never says it succeeded when it did not.

## The problem today

`find_element()` in `backend/app/agent/screen.py` still uses the team's old recorded macro: it finds each control by its position on the screen, as it was on 28 October. On most screens that works. On KX-1004 the confirm screen has one more button, **Withdraw case**, between Back and Confirm, because the applicant asked about withdrawing. The macro presses the second button: it withdraws the application. Then `check_saved()` finds a reference number on the screen and the run says "recorded".

## Acceptance criteria

1. `find_element(elements, role, name)` returns the one element with that role and that accessible name, as its docstring describes: the role matches exactly; the name ignores case and extra spaces.
2. No match: raise `ScreenError('No button named "Save" on this screen')`. More than one: raise `ScreenError('2 buttons named "Save" on this screen')`. Never guess.
3. `check_saved(elements, expected_outcome)` returns the reference only if the screen's heading is **Outcome recorded** and its notice names the outcome the agent chose; otherwise it raises `ScreenError` with the docstring's words.
4. On **Agent runs → Work one exception**, KX-1004 ends **recorded**, Request more information (R01), and **What CaseFlow Classic recorded** does not say "Case withdrawn".

## Files you change

- `backend/app/agent/screen.py`: replace the bodies of `find_element()` and `check_saved()`. Do not change `LegacyScreen` or `READ_JS`.
