# ENG-902 · Stop a run before it goes on too long, costs too much, or goes round in circles

**Type:** feature · **Priority:** Must · **Day 9, Activity 2** · **Story:** a stuck agent stops by itself

## Story

As Helen Achebe, the MLRO, I want every run of the operations agent to stop within the limits Grace and I agreed (data/Day09_Slide15_run_limits.json), so that a stuck agent hands the work back to a person instead of repeating itself and spending money.

## The problem today

`check_limits()` in `backend/app/agent/limits.py` is not built, so only the course's safety cap of 40 steps applies. On KX-1003 the record is locked by Priya Nair: CaseFlow refuses every save, and the agent presses Save again and again until the cap, about 175,000 tokens later.

## Acceptance criteria

1. `check_limits(steps, next_action, limits, started_at, now)` returns `None` when the next action may go ahead, or the reason the run must stop, as its docstring describes.
2. The checks, in this order: the step limit, the token budget (tokens in and out of every step), the time limit, and the same action (same tool, same arguments) `max_repeats` times in a row.
3. The reasons, word for word: `Step limit: 25 steps`, `Token budget: 150,000 tokens used`, `Time limit: 300 s`, `Repeating: click "Save" 3 times in a row` (use `describe()`).
4. On **Agent runs → Work one exception**, KX-1003 ends **stopped** with `Repeating: click "Save" 3 times in a row`, after 14 steps.
