# ENG-201 · Profile the client's sample data

**Type:** feature · **Priority:** Must · **Day 2, Activity 1**

## Story

As the FDE, I want every column of the client's sample export profiled against its data dictionary, so that I can tell the client what is wrong with the data before we design anything on top of it.

## Acceptance criteria

1. `profile_column(spec, values)` in `backend/app/design/profile.py` returns a `ColumnProfile` exactly as its docstring describes:
   - **missing:** a value is missing if it is `None` or only spaces
   - **format:** `invalid_pct` uses `matches_format()` against the column's expected format
   - **duplicates:** reported only for key columns
   - **personal data:** found with `PII_PATTERNS`, only in columns the dictionary does not declare as personal data
   - **issues:** in the fixed order the docstring gives
2. On the **Design & cost → Data readiness** tab, **Profile the sample** shows:
   - four readiness cards: Complete, Valid, Private, Labelled
   - a row for each of the 17 columns
   - the list of issues to take to the client

   The screen is already built: only `profile_column()` is missing.

## Files you change

- `backend/app/design/profile.py`: fill in `profile_column()`. Nothing else.

`matches_format()` and `PII_PATTERNS` are in `backend/app/design/formats.py` (done).
