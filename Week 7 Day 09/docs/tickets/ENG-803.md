# ENG-803 · Accept a webhook only if the ticketing system really sent it, just now, once

**Type:** feature · **Priority:** Must · **Day 8, Activity 3** · **Story:** nothing posts to a KYC channel unless the bank's system sent it

## Story

As Grace Mensah, a team lead, I want new KYC exceptions to appear in my team's Slack channel as soon as they are raised, and I want to trust every message there, so that my team acts on real escalations and never on a forged or replayed one.

## Acceptance criteria

1. `verify_webhook(headers, body, secret, now, seen)` in `backend/app/integration/webhooks.py` returns the event, or raises `WebhookRejected` with the first reason that applies, word for word as its docstring lists them.
2. The signature is the hex HMAC-SHA256 of `f"{t}." + body`, keyed with the shared secret, compared with `hmac.compare_digest`. The check uses the raw body bytes, before any JSON parsing.
3. A delivery more than 5 minutes old (or ahead) is refused, and so is an event id already received.
4. On **Integrations → Webhooks → Slack**, of the six test deliveries only the genuine one is accepted, and a new escalation appears in the team's channel and in #financial-crime.

## Files you change

- `backend/app/integration/webhooks.py`: fill in `verify_webhook()`. Nothing else.

The endpoint `POST /api/hooks/kyc-exceptions` (done) passes the raw body, the headers and the ids already seen, and posts to Slack only if your function returns the event.
