# ENG-302 · The bank's proof-of-address rules

**Type:** feature · **Priority:** Must · **Day 3, Activity 2 · session "rules"** · **Story:** S04

## Story

As an analyst, I want the name, address, date and issuer checks done for me, so that I spend my time on the documents that need a person, and rework drops (F05).

## Acceptance criteria

1. `check_policy(fields, app, rules)` in `backend/app/prototype/rules.py` returns four `Check`s (name, address, date, issuer), exactly as its docstring describes:
   - a check uses a field only when its status is **ok** or **confirmed**; otherwise it is **look**
   - **name:** titles and punctuation ignored; an initial matches a first name
   - **address:** same postcode and the same first number as the application
   - **date:** within `max_age_months` calendar months, counted back from the date named by `date_counted_from`, and not after the document arrived
   - **issuer:** on the approved list (`data/Day03_Slide15_approved_issuers.csv`)
2. On **Cases**, D03-007 (a mobile phone bill) fails the issuer rule, and the queue shows *Fails a rule*.

## Files you change

- `backend/app/prototype/rules.py`: fill in `check_policy()`. Nothing else.

`parse_date()`, `months_before()`, `name_parts()`, `first_number()`, `find_postcode()` and `norm_postcode()` are in the same file (done). The rules' settings are in `engagement/poa_rules.json`.
