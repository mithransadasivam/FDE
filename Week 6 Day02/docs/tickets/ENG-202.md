# ENG-202 · Check architectures against the client's rules

**Type:** feature · **Priority:** Must · **Day 2, Activity 2**

## Story

As the FDE, I want every candidate architecture checked automatically against the rules we heard in discovery, so that no option reaches the client that breaks one, and every later change is checked the same way.

## The five rules

| Rule | Where it came from |
|---|---|
| `residency`: customer data stays in the UK | Helen (MLRO) |
| `public_ai`: no public AI services | Helen |
| `read_only`: only people write to CaseFlow; its API is read-only | Tom |
| `human_decides`: a person makes every KYC decision | Helen |
| `audit`: every model call is logged | Helen |

## Acceptance criteria

1. `check_architecture(arch)` in `backend/app/design/architecture.py` returns `Violation` objects exactly as its docstring describes, grouped by rule in the order above.
2. Option A meets every rule. Option C breaks them six times.
3. On the **Architectures** tab, the rule list shows a tick or a cross for each rule, and the canvas marks every box and arrow that breaks one in red. The screen is already built: only the check is missing.

## Files you change

- `backend/app/design/architecture.py`: fill in `check_architecture()`. Nothing else.

- `cd frontend && npx playwright test e2e/architecture.spec.ts` → 3 passed
